1. 先建立一张地图

Compose 页面→StudioViewModel→LanApi→Python LAN / StudioService→ComfyUI / DeepSeek

页面负责“画什么、按钮怎么点”；ViewModel 负责“现在是什么状态、下一步做什么”；LanApi 负责“如何把命令发到 PC”。模型推理、项目文件和 API Key 仍在 PC。Android 是原生界面，没有用 WebView 包 Vue。

把它对应成 Java：页面 ≈ View，ViewModel ≈ 状态持有者和协调类，LanApi ≈ HTTP Client，Python ≈ 远程业务服务。这些是职责类比，不是让你把所有逻辑写进 Controller。

  1. 先读 MainActivity.onCreate：十行左右的入口。
  2. 再读 StudioShell：看页面如何切换。
  3. 再看 StudioViewModel.call 与 LanApi.rpc：知道命令如何到 PC。
  4. 最后挑一条业务：下面的图片生成或 AI 附件，把文件串起来。

本手册的 Java 代码是可编译的“阅读模型”。UI、协程和 Android 生命周期保留必要说明，不冒充能直接运行的 Java 版 Android App。生产 Kotlin 源码没有被替换。

最重要的两个区别

// Kotlin
var connected by mutableStateOf(false)
// Java 思路：字段变化时通知观察它的 UI
void setConnected(boolean value) {
    connected = value;
    notifyUi();
}

by mutableStateOf 不是普通字段，Compose 会跟踪读取并重新计算受影响的界面。上面的 notifyUi 只是 Java 类比，项目没有这个真实方法。

// Kotlin
viewModelScope.launch {
    val response = withContext(Dispatchers.IO) { api.rpc(...) }
    receive(response)
}
// Java 思路：后台请求完成后切回 UI
worker.execute(() -> {
    Response response = api.rpc(...);
    ui.execute(() -> receive(response));
});

suspend 表示函数可以挂起等待，并不意味着自动新建线程。Dispatchers.IO 才把阻塞网络操作转到 IO 调度器；viewModelScope 还与生命周期取消关联。实际代码用 Mutex 串行命令，不能只用一个随意的线程池替换。

3. Compose 不是 XML，也不是 HTML

@Composable
fun Hello(name: String) {
    Column {
        Text("你好，$name")
        Button(onClick = { /* 用户点击时执行 */ }) {
            Text("连接 PC")
        }
    }
}

读成中文：定义一块 UI；纵向排列；先显示文字，再显示按钮。Column 是竖排，Row 是横排，Box 是叠放，LazyColumn 是按需要加载的滚动列表。

Modifier.fillMaxWidth().padding(16.dp) 描述宽度和内边距，链式调用顺序可能影响布局。dp 是适配屏幕密度的尺寸，sp 用于文字。

写法项目里为什么要这样写
remember在重组之间保留对象，例如 ExoPlayer，不要每次绘制都创建播放器。
rememberSaveable保存支持恢复的输入值，例如生成表单文本；不等于永久存数据库，关闭/换项目等仍有业务清理。
LaunchedEffect(key)进入界面或 key 改变时运行协程；旧 key 对应的任务取消。素材分页由它加载。
DisposableEffect注册监听，并在离开时释放。视频预览用它移除监听、release 播放器。
onClick = { ... }副作用发生在点击时。不要在普通 Composable 函数体里直接提交生成，否则重组可能重复执行。

Java 可以理解这些职责，但不能把 @Composable 函数逐字换成普通 Java 方法，就得到同样的界面。学习目标是知道每段代码为什么存在、要改功能应该找哪里。

文件主要职责阅读提示

ChatAttachments.kt对话附件入口与卡片打开 ProjectMediaPicker 或系统 OpenDocument；选择 PC 媒体调用 context.add_media；手机上传交给 ViewModel；context.remove/clear 不删除素材。

LibraryFilters.kt主素材库筛选控件来源、所属关联、排序、回收站状态改变后重新查询；它只设置参数，不在手机重新写资产库。

5. 连接 PC 与实时同步

  1. ConnectionScreen 收集地址、固定密码、设备名，调用 vm.pair(code, name)。
  2. StudioViewModel.pair 通过 action 防止重复点击，在 IO 协程调用 api.pair。
  3. LanApi.pair 先校验局域网地址，然后 POST /pair。字段仍叫 code 是历史命名，现在实际是可记住的固定密码。
  4. PC 返回会话 token。手机用 ConnectionStore 加密保存连接密码，用 token 调用 bootstrap 获取真实状态。
  5. startSocket 打开 ws://PC:端口/events，onOpen 先发 token。
  6. 收到 type=state 的消息后，receive 替换最新状态，UI 才显示“已连接 PC · 实时同步”。
// Java 阅读模型；真实代码是协程
api.pair(address, password, deviceName);
RpcResponse bootstrap = api.rpc("bootstrap", Map.of(), null, 0);
// 随后建立 WebSocket，在 onOpen 发送 token；onMessage 接收 state
// 不能仅因为 TCP 连通就显示“项目同步成功”。

connectionEpoch 是连接代数。旧连接回调晚到时，代数不同就忽略，避免旧状态覆盖新连接。断线退避从 1 秒逐渐到最多 10 秒。4001 表示授权相关关闭，按现有逻辑重新授权。普通请求超时不会自动重试生成。

PC 地址限制在私网/回环 IPv4；HTTP 没有公网加密隧道，因此只用于可信 LAN。密码在 AndroidKeyStore 保护下存储，不把 DeepSeek key 下发给手机。

6. 一次图片 / 视频生成的完整调用链

openGeneration→defaults + 参考图片→表单校验→generation.preview→确认→submit / review.respond→PC 任务状态

打开表单

StudioShell 的图片按钮调用 vm.openGeneration("image")，视频按钮传 "video"。ViewModel 向 PC 请求 generation.defaults，并分页读取项目图片作为可选参考。默认参数与工作流目录来自 PC，手机不维护第二套 ComfyUI 图。

输入与校验

GenerationScreen 用字符串保存数字输入，例如 steps、seed、seconds。用户正在输入 "." 时不马上转 Double，而是在 value() 和 GenerationRules.validate 中检查，显示可读错误，再转成所需数字类型。

mode参考图要求
qwen_edit1–16 张
h3_i2v / quad / upscale恰好 1 张
h3_fl2v恰好 2 张，依次首帧/尾帧
h3_ref1–9 张，顺序保留
其他当前模式0 张；新模式必须与 PC 能力一起更新

本地还检查非空提示词（upscale 例外）、Long 范围种子、像素量 0.1–16、步数 0–100、视频秒数 0.2–149、放大倍率 1–8、电影 LoRA 强度 0–2。这些是当前表单边界，不保证每台 PC/每种模型都能运行，PC 仍有最终校验。

预览参数与真正执行分开

// 用 Java 表示顺序
String issue = GenerationRules.validate(parameters);
if (issue != null) showError(issue);
else call("generation.preview", payload); // PC 只返回输出规格供确认

// 只有最终确认按钮才进入下面的分支
if (generationReviewId != null) {
    call("review.respond", /* 原提案 id + accepted=true + generation */);
} else {
    call("generation.submit", /* generation + target */);
}

确认页显示实际尺寸、步数、视频帧数、对齐后的时长；点击提交后切到“任务”。AI 发起的生成走 review.respond，保留原来的操作确认流程。不能把它改成绕过审阅的 generation.submit。

真实进度从哪里来

PC 服务连接 ComfyUI、维护任务队列、保存结果，再把状态发到 /events。CreationScreens.TasksScreen 读取任务状态与 progress；UI 没有计时器伪造百分比。MediaDialog 中每 250ms 查询的是播放器已经播放的位置，不是生成进度。

“再次生成”复用旧参数再打开表单；“恢复查询”调用 task.resume，不应理解成无条件新建 GPU 任务。网络错误后的重复提交可能产生重复任务，因此先检查 PC 历史。

7. AI 的图片和视频引用

从 PC 素材库选择

ChatAttachments → ProjectMediaPicker
  → library.query(kind=image 或 video)
  → 用户选中真实素材
  → context.add_media(file)
  → PC 返回新的 context 状态
  → 附件卡片显示在输入框上方
  → 用户点击发送 → chat.send(text)

从手机导入

系统 OpenDocument 返回 content://... Uri，不是 PC 文件路径。ViewModel.importMedia 用 ContentResolver 读取文件名与字节流，边读边限制 100 MB；LanApi.upload 发送 multipart 到 /upload，metadata 带 projectId、library.import 和 kind。PC 验证和保存后返回真实文件标识，再逐项 context.add_media。

导入前捕获项目 ID；上传后如果当前项目变了，就提示文件已保存到原项目，避免把引用误加入别的项目。

// Java 读法（省略 Android 系统选择器和网络细节）
String originalProject = currentProjectId;
UploadResult result = uploadToPc(originalProject, selectedUri);
if (!Objects.equals(currentProjectId, originalProject)) {
    showError("项目已切换，素材已保存到原项目");
    return;
}
for (String file : result.files()) addMediaReference(file);

context.remove / context.clear 只移除待发送引用，library.delete 才是进入素材回收站。AI 目前接收文字和素材引用，不能把“附件卡片显示正常”写成“模型已读懂视频”。

8. 项目数据为什么不会只改在手机上

MainActivity.kt 中的项目/角色/场景/分镜页面调用统一命令，例如 project.open、asset.add、asset.update；WorkspaceActions.kt 调用换图、关联、删除等命令。手机不直接打开 PC JSON 文件。

// 一次命令的实际协议形状，省略具体用户数据
{
  "id": "每次操作的新 UUID",
  "command": "asset.update",
  "payload": {"id": "条目ID", "name": "名称", "description": "描述"},
  "projectId": "当前项目ID",
  "revision": 12
}

revision=12 仅是协议示意，不是真实项目当前版本。PC Host 对需要冲突保护的修改检查版本，例如 asset.update、asset.link、asset.use_media、project.story。对话框打开时捕获旧 revision，保存时如果 PC 已被别的客户端修改，PC 拒绝过期写入，用户刷新后再编辑。

Android 的 Mutex 只串行当前客户端的请求，不能保护多个手机；真正的多客户端写入还依赖 PC 的串行处理、Qt 主线程分发和版本冲突检测。

删除资产条目会移除条目和关联，已有素材文件仍保留；素材回收站提供恢复。两种删除含义不同，UI 各自有确认。

9. 素材、预览与视频播放

LibraryFilters 修改 kind/source/owner/sort/trash 等查询条件。LibraryScreen 显示主素材库。ProjectMediaPicker 有独立的搜索和分页状态，选择附件不会重置主素材库筛选。

LanApi.media 只把以 /media/ 开头的已授权 URL 拼上 PC 地址。PC 会验证媒体标识；不是允许手机读任意 D 盘路径。不要把凭证 URL 贴到公开日志。

图片用 Coil 显示，支持双指缩放和适应屏幕；视频用 Media3 ExoPlayer：

// Java 生命周期思路
Player player = createPlayer(url);  // remember(url)：同一预览不反复创建
onAppStop(() -> player.pause());   // 切后台暂停
onPreviewClosed(() -> player.release()); // 关闭后释放播放器资源

实际 NativeVideo 用 DisposableEffect 绑定生命周期、LaunchedEffect 更新播放位置。播放失败会显示 Media3 错误码；不能把 UI 上出现播放器当作视频已成功解码。

10. Java 文件应该怎么读

打开 带行号的 Java 源码，或者 标准 Javadoc。原始文件：java-src/StudioJavaGuide.java。用 Android Studio 的“打开文件”也可以直接看它，但不要移动到 app/src/main/java。

内容准确边界
LanApi.validateBase / GenerationRules有具体 Java 实现，可编译和运行纯逻辑检查。Map 与 JSONObject 的转换细节有少量差异，仍以 Kotlin 为准。
StudioViewModelExecutor 解释 IO / UI 切换和真实命令。省略完整协程取消、重连、播放器/Android 生命周期，不是生产替换类。
Screen / Transport / Player / ConnectionStore接口表达职责，没有提供伪造 PC 数据的实现，也不在你的设备执行生成。
其余 UI 类型用 Java 按钮事件/方法表达交互逻辑；Compose 布局详见原 Kotlin 快照。

文档自检会编译 Java 文件、生成 Javadoc，并检查地址限制和参考图校验。它不会连接你的 PC 服务、不会提交生成、不会改项目资产。

使用项目现有 JDK 21。Java 源码快照与 Javadoc 可一起复制走离线查看；部分系统 Javadoc 栏目保留英文，类和方法说明为中文。

12. PC 后端与桌面源码接着怎么看

这一册重点是你新遇到的 Android Kotlin。仓库原有 《用 Java 理解 Python 后端》保留，可接着理解桌面业务。Android 没有另做一套生成服务。

PC 文件Java 开发者可以这样理解
studio/lan/server.pyHTTP/WebSocket 服务器层：路由、认证边界、上传、序列化请求、媒体响应。
studio/lan/host.py适配器和权限边界：命令/字段白名单、授权项目、敏感字段清理、版本冲突、转交 StudioService。

studio/service.py应用业务服务：原桌面与手机共用的项目、队列、生成和 Agent 操作。
studio/desktop.py保留 PySide6 / QWebChannel 桌面，并集成“手机连接”入口。

手机发 HTTP 命令，桌面发 QWebChannel 命令，两条入口汇到 PC 业务层。今后加新命令要同时核对 PC 白名单和确认机制，不应直接开放任意文件路径或任意 Python 调用。
