## 如何排除错误归因

重新提交相同模型、提示词、参考图片、尺寸和 40 步，每次只改变种子或画布创建方式：

1. 种子 42 + 显式空白画布：仍然出现同样的杂点和异常人物位置。
2. 种子 100 + Agent 原来的编码节点画布：得到与用户手动结果相同的正常图像内容。
3. 种子 42 + Agent 原来画布重复执行：复现原来的异常图像内容。

三次重跑与对应原图的 RGB 像素逐个比较全部相同（平均差值、最大差值均为 0），不是只凭缩略图作出的判断。

对照排除了采样步数不足以及画布分支造成该次异常。能确认的是，这份模型、提示词和参考组合在种子 42 上产生了不理想的确定性结果；原软件始终固定默认种子 42，导致 Agent 每次默认都会重复这个结果。没有据此宣称找到了模型内部数值问题，也没有把切换随机种子描述为保证所有图片质量的算法修复。

本机节点代码和 [ComfyUI 的官方源码](https://github.com/Comfy-Org/ComfyUI/blob/master/comfy_extras/nodes_qwen.py) 均表明编码节点第三个输出是按第一参考图尺寸创建的空白 latent，并不是“直接对第一张图继续加噪”。保留用户批准的工作流分支及参考顺序。

## 修改后的行为

- 手动打开新生成窗口、Agent 准备新生成建议时，都通过同一后端默认参数函数选择新种子，默认显示明确的实际步数。
- 窗口中的种子刷新按钮可换一个随机种子。用户仍可手工填写 42、100 或其他合法值复现结果。
- 参数审阅、确认、排队、执行及任务恢复不会再次随机化已选种子。
- 使用历史参数再次生成仍保留原种子；要尝试不同结果，点击刷新按钮。旧异常图片不会被替换或删除。
- 0 步的旧兼容输入继续支持，提交新任务前解析为实际步数并写入历史：Qwen 40、Krea2 8、四视图 10、H3 8、RFMSR 15。拒绝非整数步数。
- 项目 schema、素材 ID、工作流模型/LoRA、参考顺序与尺寸、Windows 凭据存储保持兼容。冻结 v1.0.0、上一版 v1.1.0 保留。

## 验证与边界

具体结果见随包的 `VALIDATION-v1.1.1.json`。对照测试与实际生成使用独立验收目录，没有更改用户项目中的旧结果，也没有重启或关闭独立 ComfyUI。随机种子只解决固定种子反复复现同一坏结果的问题，模型产生的语义、构图和质量仍需用户挑选；本版不自动检测图片质量或盲目重试。

Windows 包解压后保留整个 `XY-Studio` 目录，运行 `XY-Studio.exe`。同一项目先关闭旧版再打开新版；原 DeepSeek Key 从 Windows 凭据管理器读取。源码正式入口仍为 `main.py`，Vue 为唯一正式前端。
